# NexaReply — UX კვლევის საფუძველი

## კვლევის სტატუსი და მიზანი

ეს დოკუმენტი აღწერს **დასაწყისის ჰიპოთეზებს** და არა ჩატარებული კვლევის შედეგებს. NexaReply-ის პირველი ვერსია Georgian-first AI გაყიდვების სამუშაო სივრცეა მცირე ბიზნესებისთვის, რომელთაც Facebook Messenger-ში მიღებულ შეკითხვებზე სწრაფი, ზუსტი და კონტროლირებადი პასუხი სჭირდებათ. სანამ პროდუქტი რეალურ მომხმარებლებთან გამოცდება, ქვემოთ აღწერილი პერსონები და საჭიროებები უნდა ჩაითვალოს დასამოწმებელ ვარაუდებად.

| კვლევითი კითხვა | სამუშაო ჰიპოთეზა | პროდუქტის გადაწყვეტილება, რომელსაც ამოწმებს |
|---|---|---|
| როგორ ინარჩუნებს მფლობელი კონტროლს AI-ის პასუხებზე? | მფლობელს სურს დაინახოს კონტექსტი, AI-ის სტატუსი და პასუხის წინასწარი ვარიანტი ერთ ეკრანზე. | Inbox-ში მკაფიო „AI აქტიურია“ და „ადამიანმა ჩაიბარა“ მდგომარეობები, editable პასუხი და audit trail. |
| რა არის ყველაზე სარისკო გაყიდვების შეცდომა? | არაზუსტი ფასი, მარაგი ან განვადების პირობა უფრო აზიანებს ნდობას, ვიდრე შედარებით ნელი პასუხი. | მხოლოდ კატალოგითა და ცოდნის ბაზით დამოწმებული პასუხები; უცნობი შეკითხვის escalation. |
| რას ელის Messenger-ის მომხმარებელი? | მყიდველს სურს მოკლე, ბუნებრივი ქართული პასუხი, რომელიც კონკრეტულად პასუხობს ფასს, ფერს, მარაგს ან განვადებას. | შეკრებილი შეტყობინებების ერთიანი პასუხი, მოკლე tone და product-aware პასუხები. |
| როგორ უნდა გამოჩნდეს დემო? | ვიზიტორი უფრო ადვილად გაიგებს ღირებულებას, თუ შესვლა და კონფიგურაცია არ დასჭირდება. | ღია Demo Mode და „TechZone Demo“ კონტექსტი. |

## ძირითადი პერსონები

### პერსონა A — ბიზნესის მფლობელი ან ოპერატორი

ეს არის **ვარაუდზე დაფუძნებული პერსონა**. ის შეიძლება იყოს მობილური ტელეფონების მაღაზიის მფლობელი, გაყიდვების მენეჯერი ან მცირე გუნდის ოპერატორი. მისი ყოველდღიური ამოცანაა მაღალი მოცულობის Messenger შეტყობინებებზე სწრაფი რეაგირება, სწორი პროდუქტის შეთავაზება და ისეთ შემთხვევებზე ჩართვა, სადაც ავტომატიზაცია უსაფრთხო არ არის.

| ასპექტი | აღწერა |
|---|---|
| მთავარი მიზნები | სწრაფად დახუროს მაღალი განზრახვის მქონე მოთხოვნები, შეამციროს გამოტოვებული ლიდები, თავიდან აიცილოს არაზუსტი დაპირება. |
| მაღალი რისკის ამოცანები | AI პასუხის დამტკიცება, human takeover, უცნობი საკითხის ticket-ად გადაქცევა, ლიდის/დრაფტ-შეკვეთის შემოწმება. |
| ძირითადი მოლოდინი | ნახოს ვინ წერს, რას კითხულობს, რის საფუძველზე შეადგინა AI-მ პასუხი და რა ქმედება დარჩა. |
| შესაძლო ბარიერები | შეზღუდული დრო, ტექნიკური ექსპერტიზის ნაკლებობა, მონაცემების სიზუსტის მიმართ სკეპტიციზმი. |
| ხელმისაწვდომობა | კლავიატურით სწრაფი ნავიგაცია, მკაფიო focus, მაღალი კონტრასტი და მოკლე, გასაგები ქართული copy. |

### პერსონა B — Messenger-ით მოსარგებლე მყიდველი

ეს არის **ვარაუდზე დაფუძნებული პერსონა**. ის ხშირად წერს რამდენიმე მოკლე შეტყობინებით, მაგალითად ჯერ ეკითხება კონკრეტული მოდელის ხელმისაწვდომობას, შემდეგ ფასს და ბოლოს ფერს. მას არ აინტერესებს შიდა ოპერაციული პროცესი; სურს დროული, ზუსტი და თავაზიანი ინფორმაცია ქართულად.

| ასპექტი | აღწერა |
|---|---|
| მთავარი მიზნები | გაიგოს ფასი, მარაგი, ფერი, განვადება, მიწოდება ან ფილიალის ინფორმაცია. |
| მაღალი რისკის ამოცანები | ერთმანეთის მიყოლებით გაგზავნილი შეტყობინებების სწორად გაერთიანება; გაურკვეველი შეკითხვის უსაფრთხოდ გადაცემა ადამიანთან. |
| ძირითადი მოლოდინი | ერთიანი პასუხი, რომელიც არ იმეორებს კითხვას და არ ჰპირდება დაუდასტურებელ პირობებს. |
| შესაძლო ბარიერები | არაზუსტი პასუხი, ზედმეტად ფორმალური ენა, AI-ის მიერ შეტყობინებების ნაადრევად დამუშავება. |
| ხელმისაწვდომობა | მოკლე წინადადებები, მკაფიო CTA-ები, მარტივად წასაკითხი ქართული ტექსტი მობილურზე. |

## მოკლე ქართული usability-test გეგმა

პირველი ტესტი რეკომენდებულია 5–7 მონაწილით თითოეული ძირითად სეგმენტიდან, რათა გამოვლინდეს მთავარი usability პრობლემები; შედეგები არ უნდა განზოგადდეს რაოდენობრივად დამატებითი კვლევის გარეშე. მონაწილეებს უნდა მიეცეთ ინფორმირებული თანხმობა, ხოლო ეკრანის ჩანაწერი და შენიშვნები უნდა დამუშავდეს მხოლოდ კვლევის მიზნებისთვის.

## ვალიდაციის მეტრიკები

უსაბუთო რიცხვობრივი დაპირებების ნაცვლად, პირველ ტესტში უნდა გაიზომოს task completion, time-on-task, შეცდომები, მონაწილეების confidence და 5-ქულიანი თვითშეფასება. შემდგომი release-ისთვის პრიორიტეტი ენიჭება ისეთ პრობლემებს, რომლებიც აფერხებს takeover-ს, ticket escalation-ს, პასუხის დამტკიცებას, მონაცემის სანდოობის აღქმას ან მობილურ ნავიგაციას.
