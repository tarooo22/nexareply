# NexaReply — Persistent Foundation Contract

## Approved platform decision

NexaReply retains the existing **React, Express, tRPC, Drizzle, MySQL/TiDB and Manus OAuth** foundation. The application will not introduce Supabase or PostgreSQL in this phase. This keeps the deployed runtime compatible with the provisioned database while every business operation is placed behind a repository/service boundary so a future data-provider migration does not require UI component rewrites.

## Isolation and access model

All persisted business tables are organization-scoped. The server resolves an actor, membership, and organization before any protected request reads or mutates business data.

| Scope | Access rule |
|---|---|
| Authenticated workspace | A signed-in user must have an active membership for the requested organization. |
| Owner | Can manage organization settings, memberships, integrations, jobs, and all business entities. |
| Sales operator | Can work with products, knowledge, conversations, tickets, leads, and draft orders; cannot manage memberships or integration secrets. |
| Public Demo Mode | Is explicitly limited to the sanitized TechZone Demo organization and public demo procedures. It cannot select or read another organization. |

The client may pass an organization identifier only as a route or UI selection. The server validates that identifier against the authenticated membership or the single public Demo organization; client-side role selection never authorizes an action.

## Layer boundaries

| Layer | Responsibility | Forbidden responsibility |
|---|---|---|
| React pages/components | Render typed query data, call tRPC mutations, display loading/error/empty states. | Direct SQL, database-specific types, secret access, tenant authorization. |
| tRPC router | Validate input, establish actor/organization scope, map errors to API responses. | Business-rule duplication or raw query construction. |
| Services | Apply workflow rules: AI safety, ticket creation, idempotency, handoff, analytics calculations, import validation. | UI state ownership. |
| Repositories | Perform scoped Drizzle reads/writes against the schema. | Permission decisions based solely on untrusted input. |
| Schema/migrations | Define tables, indexes, foreign keys, and unique idempotency constraints. | Application workflow behavior. |

## Persistent entity groups

The schema is divided into identity (`organizations`, `organization_memberships`, `plans`, `usage_counters`), catalog/knowledge (`products`, `product_variants`, `product_imports`, `knowledge_facts`, `knowledge_documents`), conversations (`conversations`, `conversation_participants`, `messages`, `tickets`, `ticket_replies`), sales (`leads`, `draft_orders`, `order_items`), operations (`notifications`, `audit_events`, `background_jobs`, `meta_webhook_events`) and configuration (`integration_settings`, `meta_connections`, `meta_oauth_sessions`). Every business table contains `organizationId` directly, or has a verified parent that does.

## Demo AI safety contract

The server-side Demo Provider reads the current organization’s active product variants and active knowledge facts. It may return a draft only when the factual reply can be grounded in those records. It never invents price, stock, installment, warranty, delivery, working hours, or location.

For an ungrounded question, the service performs a single transaction that records a safe Georgian holding reply, creates or reuses one `needs_human` ticket through a unique idempotency key, creates or reuses an owner notification, marks automatic processing paused, and emits audit events. Human takeover prevents a queued or newly created Demo AI job from adding an automated draft.

## Job and debounce contract

`background_jobs` is the durable source of truth for conversation processing. A customer message records its inbound event identity and then transactionally upserts an active `process_conversation` job using an organization-and-conversation dedupe key. A following inbound message resets the pending job’s `scheduledAt`; completed or failed jobs are not reused.

| Capability | Current foundation | Production guarantee requirement |
|---|---|---|
| Idempotency | Persisted event/job/ticket/notification dedupe keys | Already enforced in database constraints and service checks. |
| Job scheduling | Persisted job table and worker adapter contract | Requires a deployed scheduler/worker configuration. |
| 10-second debounce | Target timestamp can be saved precisely | Not guaranteed on the current autoscaling request runtime. |
| Production worker | Intentionally not enabled in this phase | Requires durable worker hosting or an equivalent queue/scheduler configuration. |

No browser timer is treated as durable processing. No claim of production-grade 10-second execution is made until the worker infrastructure is configured and verified.

## Migration and test criteria

The schema migration was generated by Drizzle and applied through the managed SQL tool. The persistent TechZone Demo seed is idempotent and verifies the live database path without exposing another organization to the public route.

Current automated coverage verifies CSV/XLSX import parsing and malformed-row rejection, safe Demo AI fallback behavior, human takeover blocking, stable escalation dedupe keys, session logout, Meta disabled-state behavior, webhook challenge/HMAC verification, repeated inbound-event suppression, safe delivery failure state, and both helper-level and router-level owner authorization. Router-level tests prove that an operator is rejected before data access on owner-only integration reads, Meta connection procedures, membership reads, membership role changes, and catalog import commit.

The remaining production validation requirements are end-to-end Meta verification against an approved real Meta App/Page, real external-delivery retry and policy-window verification, and a deployed durable-worker test. Secrets stay server-side and are supplied only through managed configuration. The full operating procedure and immutable 10-second debounce limitation are in [`META_SETUP.md`](../META_SETUP.md).
